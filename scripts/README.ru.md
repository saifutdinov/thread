# Запуск Нитки на своём сервере

[English](README.md) | [Русский](README.ru.md)

От чистого сервера до первой ссылки-приглашения примерно за десять минут. Всю работу делают четыре скрипта: каждый пишет, что делает, и его можно безопасно запускать повторно.

## Что понадобится

- **Сервер (VPS)** с публичным IPv4-адресом: 1 процессор, 1 ГБ памяти (с 2 ГБ комфортнее), 10 ГБ диска. Ubuntu 22.04 или 24.04, либо Debian 12 или 13. Подойдёт любой хостинг, в том числе облака, где сервер стоит за NAT 1:1: установщик сам найдёт локальный адрес.
- **Домен или поддомен**, например `chat.example.org`, с **A-записью** на IP сервера (только IPv4: AAAA-запись не добавляйте). Создайте её заранее: HTTPS-сертификат выпускается на это имя, и это возможно, только когда имя уже ведёт на ваш сервер.
- **Доступ по SSH** под `root` или пользователем с `sudo`. В командах ниже стоит `sudo`; если вы вошли как `root`, его можно не писать (в минимальном Debian `sudo` вообще нет).

## По шагам

**1. Зайдите на сервер и скачайте код.**

```bash
ssh root@<ip-сервера>
apt-get update && apt-get install -y git
git clone https://github.com/saifutdinov/thread.git
cd thread
```

**2. Подготовьте сервер:** Docker, файрвол, подкачка на маленьких машинах, автоматические обновления безопасности.

```bash
sudo scripts/setup-server.sh
```

Если у хостера есть свой файрвол в панели, откройте там те же порты (см. [Порты](#порты)).

**3. Установите и запустите чат** со своим доменом:

```bash
sudo scripts/install.sh chat.example.org
```

Скрипт попросит подтвердить публичный IP сервера, создаст секреты в `.env`, соберёт приложение из этого репозитория (в первый раз несколько минут), получит HTTPS-сертификат и покажет **ссылку для первого пользователя**.

**4. Откройте ссылку** на телефоне, введите имя и сохраните пароль, который выдаст приложение. Когда оно предложит, установите его на экран «Домой». Всех остальных приглашаете уже из приложения.

## Команды

| Команда | Что делает |
|---|---|
| `sudo scripts/setup-server.sh` | Готовит свежий сервер (один раз) |
| `sudo scripts/install.sh <домен>` | Первый запуск; повторные запуски сохраняют `.env` и перезапускают только изменённое |
| `sudo scripts/status.sh` | Проверяет контейнеры, HTTPS и сертификат, ретранслятор звонков |
| `sudo scripts/status.sh --logs` | Последние строки логов всех контейнеров |
| `sudo scripts/update.sh` | Обновляет и перезапускает: если сервер ставили из `main`, остаётся на `main`, иначе берёт последний релиз |
| `sudo scripts/update.sh release` | Переходит на последний релиз (тег `v*`) |
| `sudo scripts/update.sh main` | Переходит на самый свежий код из `main` |

`update.sh` никогда не откатывается на более старый код: база обновляется только вперёд.

Скрипты - обёртка над обычным Docker Compose. То же самое вручную:

```bash
docker compose -f deploy/docker-compose.yml --env-file .env up -d --build   # запустить / применить изменения
docker compose -f deploy/docker-compose.yml --env-file .env ps              # что запущено
docker compose -f deploy/docker-compose.yml --env-file .env logs -f app     # лог приложения
docker compose -f deploy/docker-compose.yml --env-file .env down            # остановить (данные остаются)
```

## Порты

| Порт | Зачем |
|---|---|
| 22/tcp (или ваш порт SSH) | Ваш доступ к серверу |
| 80/tcp | Получение HTTPS-сертификата, переадресация на HTTPS |
| 443/tcp, 443/udp | Сам чат (HTTPS, HTTP/3) |
| 3478/tcp, 3478/udp | Звонки: ретранслятор для устройств, которые не видят друг друга напрямую |
| 49160-49200/udp | Звонки: звук и видео через ретранслятор |
| 7882/udp, 7881/tcp | Групповые звонки: звук и видео через SFU (TCP в запас, где UDP не проходит) |

Без портов звонков чат работает, а звонки соединяются, только если устройства видят друг друга напрямую (в мобильных сетях это редкость).

## Где что лежит

- **`.env`** рядом с этой папкой: домен, публичный и локальный IP сервера и три секрета. `PASSWORD_PEPPER` входит в каждый пароль: если его потерять или изменить, войти не сможет никто, даже с копией базы. **Сохраните копию `.env` вне сервера**, например в менеджере паролей.
- **Тома Docker:** `thread_data` (база и зашифрованные файлы), `thread_caddy_data` (сертификат).

Сообщения, фото и файлы шифруются на устройствах, сервер хранит только шифротекст. Имена, кто с кем и когда переписывается, не шифруются, поэтому с сервером и его бэкапами обращайтесь бережно.

## Бэкапы

Приложение умеет раз в сутки делать резервную копию, зашифрованную вашим ключом, так что даже сам сервер не может прочитать свои бэкапы.

1. **На своём компьютере** (не на сервере) установите [age](https://age-encryption.org) и создайте ключ:
   ```bash
   age-keygen -o thread-backup.key
   ```
   Он напечатает открытый ключ `age1...`. Храните `thread-backup.key` вне сервера, рядом с копией `.env`.
2. **На сервере** добавьте открытый ключ в `.env` и примените:
   ```bash
   echo 'BACKUP_RECIPIENT=age1...' | sudo tee -a .env
   sudo scripts/install.sh
   ```
   Снимки появятся в томе `thread_data` в папке `backups/`, хранятся последние 7 (`BACKUP_KEEP`).
3. **Вне сервера:** укажите S3-совместимый бакет (`BACKUP_S3_ENDPOINT`, `BACKUP_S3_REGION`, `BACKUP_S3_BUCKET`, `BACKUP_S3_ACCESS_KEY`, `BACKUP_S3_SECRET_KEY` в `.env`), и каждый час туда будут уходить новые снимки и файлы: сначала файлы снимка, затем `db/<имя>.db.age`, последним `db/<имя>.db.age.manifest.json`. Снимок с manifest загружен полностью; если загрузка не удалась, она повторится через час. Настройте в бакете правило жизненного цикла на префикс `db/` (например, удалять через 30 дней), оно должно охватывать и `.age`, и `.manifest.json`. Префикс `media/` не трогайте: его файлы нужны и живой базе, и сохранённым снимкам, поэтому пересобирать его только по живой базе нельзя.

Рядом с каждым снимком лежит каталог `<имя>.db.age.media/`: manifest и hard link на каждый прикреплённый файл этой версии базы, так что сообщение, удалённое после снимка, не теряет свой файл в бэкапе. Hard link не копирует содержимое, но держит место, пока его снимок не удалён, а файловая система тома должна их поддерживать. Снимок прежней версии без такого каталога не считается полным: после обновления сервер сразу сделает новый. Вложения, уже потерянные старыми снимками, так не вернуть.

**Восстановление:**

```bash
# 1. Выберите снимок, у которого есть manifest, и скачайте оба файла
rclone copyto <remote>:<bucket>/db/thread-<время>.db.age snapshot.db.age
rclone copyto <remote>:<bucket>/db/thread-<время>.db.age.manifest.json manifest.json
# 2. Расшифруйте своим ключом
age -d -i thread-backup.key -o thread.db snapshot.db.age
# 3. Скачайте файлы именно этого снимка (jq и rclone ставятся отдельно)
jq -r '.files[]?' manifest.json > media-files.txt
rclone copy <remote>:<bucket>/media ./media --files-from media-files.txt
# 4. До остановки приложения проверьте SQLite, список файлов и размеры
python3 scripts/verify_backup.py --database thread.db --manifest manifest.json --media ./media
```

Для копии на сервере вместо S3 достаньте из тома `thread-<время>.db.age` и его каталог `thread-<время>.db.age.media` (`docker compose -f deploy/docker-compose.yml --env-file .env cp app:/data/backups/thread-<время>.db.age .`, так же для каталога) и передайте проверке `manifest.json` из этого каталога и сам каталог как `--media`. Проверка не расшифровывает файлы: их ключи остаются на устройствах. После восстановления откройте несколько старых вложений на устройстве с ключами.

Затем остановите приложение, положите `thread.db` и папку `media/` в том `thread_data` (владелец `65532:65532`, старые `thread.db-wal` и `thread.db-shm` удалите), верните свой `.env` с прежним `PASSWORD_PEPPER` и запустите. Ключи хранятся на самих устройствах, поэтому переписка снова откроется на тех же телефонах и компьютерах.

## Если что-то не работает

- **Не выпускается сертификат** (`https://` не открывается): A-запись должна вести на этот сервер, а порт 80 быть открыт, в том числе в панели хостера. Изменения DNS расходятся до часа. Потом снова `sudo scripts/install.sh`.
- **Звонки соединяются только по Wi-Fi, а в мобильной сети нет:** закрыты порты звонков, чаще всего в файрволе панели хостера.
- **Первая ссылка истекла** (24 часа), а зарегистрироваться никто не успел: `docker compose -f deploy/docker-compose.yml --env-file .env restart app`, затем `sudo scripts/install.sh` покажет новую.
- **iPhone:** регистрируйтесь и пользуйтесь приложением с иконки на экране «Домой», а не из Safari: у Safari и установленного приложения раздельные данные, и уведомления приходят только в установленное.
- Всё остальное: `sudo scripts/status.sh --logs`.

## Удаление

`docker compose -f deploy/docker-compose.yml --env-file .env down` останавливает всё и сохраняет данные. С флагом `-v` **все данные и сертификат удаляются** безвозвратно.
