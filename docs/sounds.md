# Сообщения и звуки участников звонка

В настройках «Звуки» отдельно выбираются входящий звонок, гудки, новое сообщение, вход в звонок и выход. Для каждого доступны встроенные сигналы, «Без звука» и свой аудиофайл до 3 МБ. Выбор и файл остаются на этом устройстве. Вход по умолчанию звучит восходящими нотами, выход нисходящими.

Новое чужое сообщение звучит и в открытом чате. Во время разговора звук сообщений в приложении по умолчанию выключен; его можно отдельно включить в «Звуках». Между сигналами сообщений любого чата выдерживается пауза 1,5 секунды: сигналы, попавшие в паузу, пропускаются и не накапливаются. Системные заметки, показанные самой страницей, также учитывают выключение и паузу, даже до разблокировки Web Audio. Свои сообщения, правки, повторы, старая история и записи об успешно завершённом звонке не дают сигнала нового сообщения. Скрытая страница с включённым push оставляет звук системе, чтобы он не удваивался. Настройка действует на аудио открытого приложения; звук фоновых push и закрытого приложения выбирает ОС. До первого взаимодействия браузер может блокировать собственное аудио страницы.

В личном звонке вход звучит один раз после успешного соединения, выход при завершении. В групповом звонке звучит собственный вход и дальнейший вход/выход других людей. При входе в уже заполненную комнату нет серии звуков за всех присутствующих. Несколько вкладок/устройств одного пользователя считаются одним человеком: сигнал входа даёт первое подключение, выхода последнее отключение. События своей второй вкладки не дают дополнительного сигнала.

Переподключение своего LiveKit-соединения и повторные события не воспроизводят вход/выход заново. Во время восстановления состав принимается новым снимком без сигналов. Если связь теряет другой участник и SFU действительно удаляет его из комнаты, для оставшихся это обычный выход и последующий вход.

Встроенные сигналы сообщений/участников короче секунды. Свои файлы для этих событий проигрываются один раз, до 5 секунд; только входящий звонок и гудки зацикливаются. Звуки идут локально, отдельно от дорожки микрофона и музыки. При отсутствии аудиоконтекста сообщение/звонок продолжает работать.

В PCM-кэше одноразовых видов хранятся только первые пять секунд, а не весь декодированный файл. Сам Web Audio сначала декодирует исходник целиком, поэтому пиковая память во время загрузки может быть выше. Предпросмотр играет один раз, включая файл входящего звонка, и заканчивается по настоящему завершению короткого файла; верхняя граница предпросмотра шесть секунд.

Проверки: реальные обработчики сообщений и личных звонков, состав группы с дубликатами/несколькими устройствами/переподключением, одноразовые файлы и освобождение AudioContext, обе локализации и production build. Браузерный прогон использует настоящий Go, WebRTC, Web Audio и LiveKit.

На физических iPhone/iPad ещё нужно проверить запуск сигнала рядом с getUserMedia, а на колонках акустическое эхо: локальный сигнал не смешивается программно с микрофоном, но может попасть в него через воздух.
