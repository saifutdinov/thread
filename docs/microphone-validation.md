# Проверка моделей и прослушивания микрофона

2026-11-04, Windows x64.

## Выполнено

- `scripts/check.sh`: успешно. Go 1.27 gofmt/vet, golangci-lint (0 issues),
  Go race-тесты, 185 веб-тестов, LiveKit HTTP/WS proxy test, production build,
  проверка восстановления Python и отсутствие добавленного U+2014.
- `BROWSER_BINARY=<Chrome> npm run test:mic`: настоящие RNNoise и DeepFilterNet3
  загружаются и дают конечный ненулевой PCM; browser/off используют правильные
  capture constraints. Все синтетические тесты используют `--mute-audio`.
- На настоящей RNNoise измерена задержка 960 сэмплов корреляцией входа/выхода.
  Кадровый адаптер добавляет 480; dry/wet выровнены на 1440 сэмплов (30 мс).
- UI: начало проверки без автоматического воспроизведения, явное прослушивание,
  смена RNNoise на DFN3 с сохранением камеры и прослушивания на 25%, изменение усиления, закрытие всех
  принадлежащих проверке контекстов/дорожек. Общий контекст уведомлений живёт
  по прежним правилам sounds.ts и не считается ресурсом проверки.
- Сохранённый отключённый аудиовывод не мешает проверять микрофон: используется
  вывод по умолчанию с понятным сообщением.
- Позднее разрешение после закрытия освобождает захват. Ошибка загрузки DFN3
  переключает на браузерное подавление с предупреждением. Остановка дорожки во
  время загрузки не вызывает нового getUserMedia.
- Браузерные проверки выполняются под CSP с `script-src 'self' 'wasm-unsafe-eval'`
  и `worker-src 'self'`. Ни одного запроса во внешний сервис.
- Исходники дополнительно проверены reviewer-агентом согласно agent-guide:
  незакрытых blocker/major замечаний нет.
- `npm run test:stream-volume`: Chromium, голос и стрим регулируются независимо,
  25%/0%, настройка из окна звонка и из настроек, сохранение при сворачивании.
  Голос 40% и стрим 0% сохраняются после размонтирования/возврата экрана;
  новый звонок за блокировкой сразу получает голос 100%.
- `group-volume.test.ts` и регрессия подписки в `group-startup.test.ts`:
  голос/экран/музыка/другой участник, некорректные числа и применение выбранной
  громкости до attach каждой заменённой дорожки.
- Голос и экран регулируются participant API LiveKit,
  напрямую меняется только Unknown-музыка текущего плеера. До изменения четыре
  целевые проверки воспроизводили обход SDK-кэша и обработку постороннего источника.
  Теперь настоящие RemoteParticipant проверяют кэш до публикации экрана,
  музыку до/после экрана, замену participant после reconnect, нулевой уровень,
  независимость другого участника, NaN/Infinity и предел истории 100.
- В Chromium настоящие RemoteAudioTrack и audio-элементы подтвердили уровни:
  голос 60%, экран/музыка 25% и 0%, другой участник 100%, замена музыки и
  восстановление SDK-кэшей/уровней нового participant, когда музыка пришла первой.
  Тестовые экспорты добавляются только Vite-сервером сценария, в production их нет.
- Ревью выявило удержание нового захвата при долгой подготовке DFN3.
  Регрессии теперь останавливают групповой и заменяемый личный микрофон до
  завершения подготовки. Chromium требует закрытия захвата/AudioContext и
  завершения AbortError до отпускания зависшей загрузки модели.
- Последний выбранный микрофон не перезаписывается поздним результатом.
  Отдельный тест удерживает replaceTrack предыдущего выбора, отклоняет новое
  разрешение и проверяет, что отправляемый микрофон остаётся живым.
- `CALL_CYCLES=1 test:calls` локально: декодирование аудио/видео, очистка
  ресурсов, перезапуск Go, потеря только сигналинга, поздние разрешения,
  последовательные звонки и восстановление зашифрованного SFU-медиа после
  остановки/перезапуска настоящего LiveKit. Также пройден сценарий слышимости личного звонка до/во время/после блокировки приложения.
  Устройства синтетические, звук заглушён.
- Браузерные сценарии используют раздельные Vite-кэши и заранее определённые
  зависимости Preact, чтобы холодная оптимизация не перезагружала runtime посреди теста.

## Дополнительное ревью владельца

- R1: browser/off без эффектов не создают граф; переходы gate/gain/highPass
  требуют reopen. Намеренный групповой raw не заменяется SDK defaults.
- R2: held DFN3 запрос воспроизводил отсутствие входящего offer за 9 с в
  прежней production-сборке. На исправленной сборке сценарий с удерживаемой
  загрузкой прошёл: входящий и медиа появились до её отпускания. Подготовка
  имеет бюджет 3 с; явная локальная проверка модели отдельно ограничена 15 с.
  raw остаётся
  живым для native fallback, внешняя отмена не включает fallback. Загрузка
  начинается при выборе и остаётся общей фоновой операцией без захвата.
- R3: Chromium инъекции port:error и processorerror сохраняют mute, после
  unmute выход содержит настоящий ненулевой PCM; повтор ошибки не дублирует bypass.
- Отдельный Chromium запущен без autoplay override. Probe идёт через CDP
  userGesture=false: активации нет, контекстов 0, native suppression включён,
  тоста ошибки нет. Обычный Playwright evaluate сам даёт gesture и не подходит.
- Зависший resume ограничен и отменяется; camera default восстановлен; камера
  сохраняется при смене модели, уровень монитора 25%. Общее владение запросом
  вынесено в mic-request.ts и экспортируется через mic.ts.
- Linux CI дополнен отдельной обязательной Firefox-джобой с fake capture и
  заглушённым PulseAudio null sink 48 кГц. Ожидания browser evaluate и resume
  ограничены; логи стадий различают capture/prepare/analyse. PCM-проверка ждёт
  preload/компиляцию DFN3 и использует явный preview-бюджет 15 с; отдельная
  cold-offer проверка сохраняет бюджет звонка 3 с.
  Mic переносит реальный sampleRate контекста в preview: Firefox может не
  публиковать частоту в getSettings() выходной дорожки.
  Локальная Windows-сборка Firefox 153.0 Playwright 1538 не запускается из-за
  SxS зависимости mozglue; это ограничение тестового окружения, не проверка Firefox.

## Нагрузка DFN3

Машина сессии: AMD Ryzen 7 5700X3D, 8 ядер/16 потоков, Windows x64, Chrome.
На среднем ноутбуке замеров нет. При callback 128/48000 бюджет 2,67 мс;
последние окна по 64 инференса дали среднее 0,81/0,94/0,94 мс, p95 1/2/1 мс.
В первом окне, включающем прогрев, был одиночный пик 22 мс; последующие максимумы 2 мс.
Другой локальный запуск дал средние около 0,4-0,5 мс. Clock в worklet использует
performance.now при наличии, иначе Date.now; здесь видна дискретность около 1 мс.
Это измерение синтетического потока, не гарантия отсутствия щелчков или нагрузки
на другом CPU. Защита от устойчивой перегрузки проверена детерминированно:
кадры 4 мс включают обход, 0,5 мс продолжают обработку; выход остаётся конечным
и ненулевым. Начальные 32 кадра исключены из решения о sustained overload.

В Windows Git checkout переводы строк Go-файлов нормализованы в LF для gofmt;
семантических изменений Go нет. Проверка использовала установленные локальные
Go/LLVM/Node и Python. Для проверки дополнительно загружен Firefox Playwright; системные runtime/настройки Windows не менялись.

## Границы проверки

Это инженерная проверка, не сравнительное прослушивание качества. Не выполнены
слепое прослушивание реальной русской речи/шума, слабый ноутбук, Firefox на физических устройствах,
настоящие телефоны/Safari и живой групповой звонок людей на физических устройствах. Полный container
build и деплой на сервер в эту локальную проверку не входят.

Слушать себя: **Настройки → Проверить устройства → Начать проверку → Слушать себя**.
Для проверки используйте наушники. Локальный монитор воспроизводит исходящий
обработанный сигнал до кодека и сети.

Версии, лицензии, схема обработки и причины зависимостей: [ADR 0006](adr/0006-microphone-models.md).
