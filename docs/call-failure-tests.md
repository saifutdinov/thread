# Воспроизводимые тесты сбоев звонков

`web/scripts/call-failures.mjs` запускает отдельные временные базу, профили Chromium и процессы Нитки и LiveKit. Рабочий сервис и пользовательские профили не используются. Синтетическая камера читает одинаковый Y4M-поток на Windows и Linux; фоновые ограничения рендерера отключены только в тестовом браузере.

Проверяется настоящий production bundle через UI, с настоящими WebCrypto и WebRTC:

- декодирование видео с обеих сторон и остановка всех захваченных дорожек/peer connections;
- аварийная остановка Go и запуск с той же базой: личное медиа продолжает идти, сигналинг возвращается и hangup доставляется;
- закрытие клиентского WebSocket и запрет повторного подключения: потеря сигналинга не завершает здоровое медиа;
- отмена до возврата настоящего getUserMedia;
- серия звонков с проверкой ресурсов после каждого;
- остановка настоящего LiveKit на 5 секунд и восстановление группового звука/видео. До и после перезапуска RoomService подтверждает GCM у всех опубликованных аудио/видеодорожек.

Offline-эмуляция браузера не считается обрывом WebRTC. Обрыв группового медиа создаётся завершением только тестового процесса SFU. Завершение каждого принадлежащего тесту процесса и браузера выполняется в finally; путь временного каталога проверяется перед рекурсивной очисткой. При сбое каталог и снимки экранов остаются для расследования.

## Запуск

CI запускает сценарии в отдельной джобе `call-failures`, независимо от сборки контейнеров и остальных проверок. Chromium кэшируется; снимки при сбое доступны в артефакте `call-failure-screenshots` в течение 7 дней. SIGINT/SIGTERM завершают принадлежащие тесту процессы и браузеры; принудительный SIGKILL или `taskkill /F` не позволяет Node выполнить очистку.

Нужны Go из go.mod, Node из web/package.json и поддерживаемый Chromium.

```sh
cd web
npm ci
npx playwright install --with-deps chromium
npm run test:calls:setup
npm run build
npm run test:calls
```

Установщик загружает LiveKit 1.13.10 для Linux/Windows x64 с официального релиза и проверяет закреплённый SHA256 архива до распаковки. Для других платформ можно задать `LIVEKIT_BINARY`. `CHROMIUM_EXECUTABLE_PATH` позволяет использовать локальный Chrome. Загруженные инструменты в `.call-test-tools` исключены из git и production-образа.

Playwright пишет Chromium вне проекта: по умолчанию в `~/.cache/ms-playwright` на Linux, `~/Library/Caches/ms-playwright` на macOS и `%LOCALAPPDATA%/ms-playwright` на Windows. `PLAYWRIGHT_BROWSERS_PATH` меняет этот каталог. Опция `--with-deps` на Linux также устанавливает системные библиотеки через apt-get (с sudo при необходимости); для существующего Chrome можно пропустить установку Playwright и задать `CHROMIUM_EXECUTABLE_PATH`. Тестовые база и профили создаются в системном временном каталоге (`TMPDIR`/`TEMP`).

По умолчанию серия включает 3 звонка. Для длительного прогона: `CALL_CYCLES=50 CALL_HOLD_MS=10000 npm run test:calls`. Между звонками большой серии соблюдается серверный rate limit. Проверка освобождения дорожек не является измерением heap: harness намеренно удерживает ссылки на старые объекты для проверки их состояний. Физические телефоны, Bluetooth и качество реальной сети остаются в [ручной матрице](call-test-matrix.md).
