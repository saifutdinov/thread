# ADR 0007: установленные приложения

Статус: принято (2026-11-09), сделаны этап 1а (компьютеры) и этап 2 (Android).

## Контекст

Нужны приложения для Windows, macOS и Android без ограничений браузера: уведомления системы, окно поверх других, клавиша микрофона поверх игр, звонок как телефонный на Android. Бюджет без подписок.

## Решение

- **Монорепозиторий с одним веб-ядром.** Интерфейс, шифрование, звонки и шумодав остаются в `web/` и работают везде одинаково.
- **Компьютеры:** Electron (`desktop/app`). Тот же Chromium, на котором проверены E2EE, AudioWorklet с WASM и звук системы при показе экрана.
- **Android:** тонкая оболочка на Kotlin с WebView (`android/`).
- **Не Flutter:** два клиента и неподтверждённая совместимость шифрования.
- **Не Tauri:** три разных движка в звонках.
- **Сборка под свой сервер.** Приложение знает адрес одного сервера. Владелец сервера собирает приложения в своём форке: адрес, Firebase и ключи берутся из настроек форка, а сервер раздаёт готовые установщики сам (`docs/apps.md`).

### Интерфейс внутри приложения, на адресе сервера

Приложение перехватывает запросы к своему серверу (`protocol.handle`). Файлы интерфейса оно отдаёт из своего пакета с той же CSP, что и сервер (`desktop/app/lib/route.js`).

- На сервер уходят только `/api/`, `/lk/` и `/healthz`. На любой другой путь сервер отвечает своим `index.html`, поэтому приложение отвечает 404 само: код с сервера не выполняется на адресе приложения.
- Редиректы не выполняются: в главном процессе они вернули бы тело чужого адреса как ответ сервера. API сервера редиректов не делает.
- Service worker в приложении не нужен и не регистрируется. Оставшиеся от прошлого запуска стираются при старте.

- Адрес страницы совпадает с сервером, поэтому cookie сессии, WebSocket и проверки Origin на сервере не меняются.
- Взломанный сервер не может подменить код интерфейса. Это главная причина ставить приложение, а не открывать сайт.
- Цена: интерфейс обновляется вместе с приложением. Если сервер новее, приложение просит установить новую версию.

### Защита окна

- `contextIsolation`, `sandbox`, без Node в странице. Preload узкий (`desktop/app/preload.cjs`): версия, показ окна, уведомления, мост клавиши микрофона.
- Переход на чужой адрес и новые окна запрещены, внешние ссылки открываются в браузере.
- Разрешения (микрофон, камера, экран, уведомления, полный экран, выбор динамика) выдаются только своему адресу.
- Fuses:
  - `RunAsNode`, `NODE_OPTIONS` и инспектор Node выключены;
  - проверка целостности ASAR включена, приложение грузится только из ASAR;
  - cookie шифруются хранилищем системы.
- Выпущенное приложение не запускается с ключами отладки (`--remote-debugging-port`, `--inspect` и другие). Их проверяет разбор ключей самого Chromium, который понимает и `-x`, а на Windows ещё `/x` и любой регистр.
- В выпущенном приложении нет инструментов разработчика и меню View.
- В уведомлениях только значок приложения. Картинку чата присылает другой участник, а главный процесс работает без песочницы.

### Возможности приложения

- **Трей:** окно закрывается в трей, сокет остаётся, звонок звонит. Там же «Поверх других окон», «Запускать при входе» и выход.
- **Уведомления системы из главного процесса:** уведомления service worker в Electron не работают. Клик открывает чат на месте.
- **Показ экрана:** на Windows своё окно выбора и звук системы (`loopback`), на macOS 15+ системный выбор.
- **Клавиша микрофона поверх игр:** приложение запускает готовый `thread-hotkeys` и говорит с ним теми же сообщениями, что и расширение (`desktop/app/lib/talk.js`). Те же ограничения: только версия 1, смена клавиши не чаще раза в секунду. Расширение Chrome в приложении не нужно.
- **Фон:** `backgroundThrottling` выключен, проверка сокета и звонок работают в фоне.

### Сборка и подпись

- CI собирает Windows (NSIS, установка для одного пользователя без прав администратора), macOS (DMG) и Linux (AppImage). На теге в форке, где заданы адрес сервера и ключи, установщики и `SHA256SUMS.txt` уходят в релиз форка, а `scripts/apps.sh` кладёт их на сервер.
- **Windows:** без подписи, SmartScreen предупредит.
- **macOS:** только ad-hoc подпись. Apple Silicon не запускает неподписанное, а fuses меняют бинарник. Gatekeeper просит «Всё равно открыть»: установка и ручное разрешение подходят, платная подпись Apple не нужна. Как установить: `docs/install-desktop.md`.
- Платная подпись Apple и сертификаты не используются.

### Android

- **Интерфейс из APK на адресе сервера.** `shouldInterceptRequest` отдаёт файлы из assets (`www/`, сборка `web/dist`) с той же CSP, что и сервер. На сервер уходят только `/api`, `/lk` и `/healthz`, остальные пути получают 404 от приложения (`Route.kt`, те же правила, что `route.js`). WebSocket идёт в сеть напрямую.
- **Пути сервера не открываются как страница.** Переход или фрейм на `/api`, `/lk`, `/healthz` получают 404 (в приложении для компьютера переход отменяется), в CSP сервера и приложений `frame-src 'none'`: иначе ответ взломанного сервера выполнился бы на адресе приложения.
- **Исключение `/_gallery/`:** фото и видео телефона для шторки прикрепления (`Gallery.kt`) отдаёт само приложение, только на запросы страницы (не как страницу), только картинки и видео без SVG, с CSP `default-src 'none'; sandbox`. На сервер они попадают только отправленными, в зашифрованном виде.
- **Service worker запрещён:** его собственные запросы идут мимо `shouldInterceptRequest`. Слишком старый WebView без нужных функций не открывает страницу, а просит обновиться.
- **Мост к странице** (`Bridge.kt`): слушатель web-сообщений и скрипт до загрузки страницы, оба только для адреса сервера и только в главном фрейме. `JavascriptInterface` не используется: его видят все фреймы любых адресов. Страница видит тот же `window.connectApp`, что и в приложении для компьютера, с добавками для Android (`NativeApp` в `pwa.ts`).
- **Пуши через FCM** (`internal/server/fcm.go`): только данные, без блока `notification`, тот же JSON, что у Web Push. Звонки и сообщения с высоким приоритетом, «прочитано» с обычным. Ключ сервисного аккаунта сервер подписывает сам (JWT RS256), без SDK Google; файл ключа лежит только на сервере (`FCM_CREDENTIALS`).
- **Расшифровка на телефоне.** Страница отдаёт приложению копию того, что читает `sw.js`: ключи чатов, имена и картинки чатов, мои имена людей, язык, скрытие текста (`android.ts`). Приложение хранит её в файле, зашифрованном ключом из Android Keystore (`Kept.kt`), и показывает пуши по правилам `sw.js` (`Push.kt`, `Words.kt`).
- **Звонок как телефонный:** уведомление `CallStyle` с полноэкранным окном поверх блокировки и рингтоном до ответа (`Notes.kt`). «Ответить» открывает приложение и передаёт ответ странице так же, как `sw.js`; «Отклонить» отклоняет звонок на сервере без страницы. Поверх блокировки окно видно только пока звонок звонит или идёт; после него чаты снова за блокировкой. Страница снимает звонок приложения, только когда сама его показала: при старте она не сбрасывает ещё звонящий вызов.
- **Идущий звонок:** служба переднего плана с микрофоном (и камерой в видеозвонке), поэтому звонок не обрывается с выключенным экраном. Видеозвонок сворачивается в картинку в картинке.
- **Версии:** minSdk 29 (Android 10), targetSdk 36, compileSdk 37; AGP 9.4.1 со встроенным Kotlin, Gradle 9.8.2 и JDK 17 из `mise.toml`. APK подписан ключом владельца сервера из секретов его форка, `docs/apps.md`.
- **Окно не пересоздаётся** при повороте, смене темы и размера (`configChanges`): иначе пропали бы сокет и звонок. Цена: смена темы системы применяется со следующего запуска.

## Следующие шаги

1. ~~**Подписанные обновления.**~~ Сделано: CI подписывает манифест установщиков ключом Ed25519, которого нет на сервере; приложение для компьютера ставит только то, что этот ключ подписал; Android ставит APK, только если у него тот же пакет и тот же сертификат подписи, что у установленного (`docs/updates.md`). Откат запрещён: обновляется только на более новую версию.
2. **Секреты IndexedDB** (ключи чатов лежат сырыми байтами) шифруются ключом из `safeStorage`: DPAPI или Keychain.
3. **Закрепление сертификата** сервера через `setCertificateVerifyProc`: корни цепочки и запасной ключ.
4. **Кнопки «Ответить» и «Отклонить»** в уведомлении о звонке. Глобальная клавиша на macOS.
5. **Android:**
   - Firebase у каждого сервера свой: `google-services.json` в секретах форка, ключ сервисного аккаунта только на сервере в `secrets/fcm.json` (владелец 65532, права 0400) и через GitHub не проходит (`docs/apps.md`);
   - проверить на настоящих телефонах: полноэкранный звонок на Android 14+ без Google Play, звонок с выключенным экраном, пуши из России;
   - показ своего экрана с Android во второй версии;
   - закрепление сертификата и подписанные обновления вместе с компьютерами.
6. **Одна сборка для всех серверов:** адрес сервера человек вводит при первом запуске, и форк для приложений не нужен. Подпись Windows через SignPath Foundation после приёма проекта.

## Отклонённое

- Загружать интерфейс с сервера: проще, но взломанный сервер отдаёт изменённый код.
- Отдельная схема `app://`: другой Origin ломает cookie, WebSocket и проверки сервера, пришлось бы открывать CORS.
- Electron 45: вышел за три дня до решения. Взят Electron 44.9.3, ему 19 дней.
