# ADR 0005: глобальное удержание микрофона через локальный компаньон

Статус: принято (2026-11-04)

## Контекст

Браузер не получает keyup из игры или другого приложения. Звонок остаётся в браузере; для глобального удержания на Windows нужен отдельный локальный компонент. Это новая граница доверия, не часть сервера или шифрования звонка.

## Решение

- В активном окне назначаемое физическое сочетание обрабатывает браузер на Windows/macOS/Linux. Модификаторы точные: лишний Shift также отпускает сочетание. Tab не назначается; стрелки и Home/End/PageUp/PageDown требуют модификатор. Tab выходит из записи с обычным переходом фокуса.
- Для глобального ввода используется расширение Chrome/Edge с Native Messaging и `cmd/thread-hotkeys` на Windows. Хост не имеет сетевого API, не обрабатывает звук/чат и опрашивает только заданное сочетание через GetAsyncKeyState. Наружу идут булево удержание, версия и случайный маркер сеанса; скан-коды, текст и история ввода не передаются.
- Расширение принимает только главный фрейм адреса, указанного в manifest и `origins.js`. В репозитории там `https://chat.example.org`: владелец сервера подставляет свой адрес. Localhost отсутствует в manifest и списке origin. Для разработки `desktop/make-dev-extension.mjs` создаёт отдельную игнорируемую git сборку `desktop/.extension-dev`; её нельзя раздавать пользователям.
- Смена сочетания чаще раза в секунду отклоняется хостом с завершением соединения. Расширение независимо ограничивает смену с той же частотой между вкладками и перезапусками native-процесса. Повторная настройка того же сочетания (mute, новый сеанс) не ограничивается.
- Одна вкладка владеет глобальным источником только при настоящем native-соединении. Разрыв сбрасывает удержание; heartbeat страницы обнаруживает потерю за 1,5 с. После настройки, нового звонка или восстановления сначала требуется отпускание, затем новое нажатие. Пробел по умолчанию открывает микрофон при печати в других программах, поэтому интерфейс явно предлагает отдельное сочетание.
- Установка действует только в HKCU текущего пользователя. Manifest допускает только ID установленного расширения. `uninstall` сначала проверяет все значения и отказывается менять чужую регистрацию; удаляются только известные ключи и два собственных файла, без рекурсивного удаления каталога.
- Инструкция доступна прямо в приложении на RU/EN. Проверенные бинарник и папку расширения передаёт владелец сервера; автоматической загрузки исполняемого файла нет.

## Границы защиты

Разрешённая страница может использовать bridge, поэтому XSS на доверенном origin остаётся угрозой. Ограничение частоты мешает быстрому перебору клавиатуры, но не делает скомпрометированную страницу доверенной. Важны CSP приложения и проверенная установка расширения.

Открытый ключ в manifest фиксирует ID распакованного расширения, а не доказывает авторство: другое распакованное расширение с тем же ключом получит такой же ID. Разрешать native-доступ следует только проверенной сборке. Публикация подписанного расширения и компаньон для macOS/Linux остаются отдельной работой. Игры с защищённым вводом и античиты могут не допустить глобальный ввод; поддержка каждой игры не обещается.

## Проверки

Протокол и лимит частоты проверяются с управляемыми часами/каналом опроса, без sleep в host-тесте. Windows-тесты установки/удаления используют только отдельные временные ключи HKCU. Реальный браузерный прогон проверяет native host, системное сочетание без фокуса звонка, остановку service worker, переподключение и отпускание микрофона.
