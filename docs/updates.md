# Обновления приложений

Приложения обновляются с вашего сервера, без магазинов. Сервер отдаёт файлы последнего выпуска в `/api/downloads` (`internal/server/downloads.go`); их собирает CI вашего форка, а `scripts/apps.sh` кладёт на сервер (`docs/apps.md`).

## Как это работает

1. CI форка собирает `manifest.json`: имя, система, версия, размер и SHA-256 каждого установщика (`.github/workflows/ci.yml`, `apps-release`).
2. CI подписывает манифест ключом обновлений владельца сервера (Ed25519, секрет `UPDATE_SIGNING_KEY` в форке) и кладёт рядом `manifest.sig`. Секретной части ключа на сервере нет.
3. Приложение при запуске, при каждом подключении и раз в 6 часов смотрит в манифест. Есть сборка для его системы новее, чем у него: в приложении баннер «Вышла версия X» с кнопкой «Обновить».
4. Кнопка «Обновить»:

| Система | Что происходит |
| --- | --- |
| Windows | Приложение проверяет подпись манифеста и хеш файла, запускает установщик в тихом режиме, закрывается; новая версия открывается сама. |
| macOS | Проверка та же, затем открывается DMG и приложение закрывается: перетащить значок Thread в «Программы» и открыть снова. Без платной подписи Apple macOS не даёт приложению заменить себя. |
| Linux, AppImage | Проверка, файл заменяется, приложение перезапускается. |
| Linux, .deb | Проверка, открывается системная установка пакета. |
| Android | Приложение скачивает APK, сверяет хеш и проверяет, что это оно само: тот же пакет и тот же сертификат подписи, что у установленного (ключ подписи APK, `docs/apps.md`). Только тогда открывается установщик Android, который спрашивает «Установить». Первый раз Android попросит разрешить Нитке установку приложений. |
| Браузер, iPhone | Страница перезагружается, как раньше. |

Компьютерное приложение с ключом обновлений (переменная `THREAD_UPDATE_KEY`, в сборке это `updateKey` в `desktop/app/app-config.json`) не видит обновления вовсе, если подпись манифеста не сходится: ни установки, ни ссылки на скачивание. Хеш файла тоже сверяется с манифестом. Приложение, собранное без ключа, только открывает файл в браузере: человек скачивает и ставит его сам, как вручную. CI не выпустит релиз без подписи, если в приложении ключ есть.

Ключ обновлений создаёт владелец сервера, один раз: `docs/apps.md`, шаг 3.
